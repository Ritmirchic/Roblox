# PIXANIME — пиксель-арт аниме, который генерирует себя сам

Проект отвечает на вопрос «можно ли понять принцип видеогенеративных ИИ и написать
такой с нуля» двумя способами сразу:

1. **`pixanime/`** — процедурный «аниме-движок»: рисует кадр 128×128 (на выходе
   256×256), персонажей, фоны, анимацию, диалоги, звук и монтаж. Из него собирается
   сколько угодно эпизодов: сценарий — это Python-код, а не веса модели.
2. **`pixanime/ml/`** — крошечная **видео-диффузия, написанная с нуля** (flow
   matching + пространственно-временной UNet, 1.5 млн параметров), обученная на
   кадрах, которые рисует движок. Это и есть «настоящий» принцип Sora/Veo/Kling —
   только в масштабе, который влезает в CPU и 30 минут.

Готовые эпизоды лежат в `showcase/`.

| файл | что это |
|---|---|
| `showcase/ep01.mp4` | эпизод 1 «Город, где кончается лето» — 63 с, со звуком |
| `showcase/ep02.mp4` | эпизод 2 «Дождь идёт третий день» — 44 с |
| `showcase/ep03.mp4` | эпизод 3 «Три года спустя» — 36 с |
| `showcase/ai_clip.gif` | клип, сгенерированный нейросетью (не движком) |
| `showcase/ai_samples.png` | кадры из нейросети: 8 кадров × несколько сэмплов |
| `showcase/training_loss.png` | кривая обучения видео-диффузии |
| `showcase/poster.png` | контактный лист кадров из сериала |

Всё разрешение — **256×256**, 12 fps, звук — процедурный чиптюн.

## 1. Как устроен современный видеогенератор (и что из этого есть здесь)

Пайплайн Sora/Veo/Kling устроен на удивление буднично:

| компонент | «как у больших» | здесь |
|---|---|---|
| токенизация видео | 3D-каузальный VAE: `T×H×W×3 → (T/4)×(H/8)×(W/8)×d` | нет VAE: работаем в пикселях, зато 32×32×8 — честно |
| генеративная модель | DiT + flow matching / rectified flow | `TinyVideoUNet`: conv-энкодер + **temporal attention**, flow matching |
| кондиционирование | текст через cross-attention / AdaLN | класс сцены через эмбеддинг (5 классов) |
| сэмплинг | 20-50 шагов Эйлера + CFG | 24 шага Эйлера |
| декодер | VAE-decoder → кадры | прямой выход в пиксели |
| «качество» | миллиарды параметров, десятки тысяч GPU-часов | 1.5 млн параметров, 20 минут CPU |

То есть архитектурно «магия» — это 3D-токенизатор + трансформер, предсказывающий
шум/скорость. Всё остальное — масштаб и инженерия.

Формула, на которой всё держится (rectified flow, тот же принцип, что DDPM, но проще):

```
x_t = (1 - t)·шум + t·данные        # прямая между шумом и клипом
цель = данные - шум                 # модель учит поле скоростей
сэмплинг: x ← x + v(x, t)·Δt        # 24 шага Эйлера от t=0 к t=1
```

## 2. Движок: почему 128×128 и зачем всё вручную

Пиксель-арт нельзя «отрендерить в 256 и уменьшить» — он должен быть нарисован
на маленькой сетке и увеличен **целым** множителем, иначе появится мыло.
Поэтому внутреннее разрешение 128×128, а на выход — `np.repeat(...)` ×2 → 256×256.
Тот же приём используется для «крупного плана»: спрайт рисуется ×2, фон остаётся.

Модули:

| файл | ответственность |
|---|---|
| `palette.py` | палитры сцен, **дизеринг Байера** (`dithered_ramp`) — единственный способ сделать градиент в 5 цветах |
| `canvas.py` | растр с бинарной альфой, полигоны/эллипсы/линии, `inner_edge` для cel-shading, `outline` для контура |
| `font.py` | собственный шрифт 5×7 (латиница, **кириллица**, пунктуация), перенос строк, «печатная машинка» |
| `sprites.py` | параметрический чиби: 6 причёсок, 4 костюма, аксессуары, позы (наклон, шаг, моргание, рот) |
| `backgrounds.py` | крыша с сеткой-рабицей, ночная улица, комната, парк с сакурой; слои и параллакс |
| `anim.py` | `(анимация, t) → Pose` на синусоидах: дыхание, моргание, шаг, разговор, жест |
| `effects.py` | дождь, снег, лепестки, светлячки, искры, лучи, виньетка, дизеринг-переход |
| `scene.py` | `Shot`: фон + персонажи + эффекты + диалоговое окно; «мир» и UI собираются в два прохода |
| `timeline.py` | монтаж шотов, стыки через dither-dissolve |
| `encode.py` | потоковая запись H.264 через ffmpeg **и собственный GIF-энкодер** (LZW по спецификации GIF89a) |
| `audio.py` | чиптюн с нуля: квадрат/треугольник/шум, прогрессия Am–F–C–G, WAV |
| `story.py` | сценарии трёх эпизодов: титры, шоты, реплики |

Ключевая мысль: **движок даёт управляемость**. Он не «фантазирует» — он выполняет
сценарий, поэтому персонажи не меняют лицо между кадрами, а серия может быть
сколь угодно длинной (время рендера линейно, а не квадратично по качеству).

## 3. Нейросетевая часть: видео-диффузия с нуля

`pixanime/ml/model.py` — `TinyVideoUNet`:

```
[B,T,3,H,W] → conv 3×3 (вес общий по времени)
            → down ×2 (stride 2)
            → ResBlock + TemporalAttention + ResBlock   ← внимание между кадрами
            → up ×2 со skip-соединениями
            → [B,T,3,H,W]  (поле скоростей)
```

* `TemporalAttention` — честное scaled_dot_product_attention по оси `T`:
  каждая точка кадра смотрит на ту же точку в других кадрах. Именно это отвечает
  за согласованность движения (и это дешевле полного 3D-внимания).
* Кондиционирование — эмбеддинг класса сцены (`rooftop_dusk`, `street_night`,
  `room_night`, `park_day`, `rooftop_night`), подаётся в каждый ResBlock.
* Обучение — `rectified flow`: `x_t = (1-t)·x0 + t·x1`, лосс MSE по `(x1-x0)`.
* Данные — 600 клипов `8×32×32`, сгенерированных движком (он же и «датасет»).
* Сэмплинг — 24 шага Эйлера; результат апскейлится ×8 nearest для показа.

Всё считается на CPU (2 ядра): ~0.8 с/шаг, 1500 шагов ≈ 20 минут.

Честно про масштаб: 32×32×8 — это игрушка. Чтобы получить «настоящее» аниме-видео
нужны (а) датасет из миллионов клипов, (б) 3D-VAE, чтобы диффузия работала в латенте,
(в) десятки GPU-часов на обучение и (г) текст-энкодер + cross-attention для промптов.
Здесь реализован весь *механизм*, но не масштаб — и это ровно тот случай, когда
механизм важнее.

## 4. Команды

```bash
pip install -r requirements.txt          # numpy, pillow, imageio-ffmpeg, torch (для ml)

# эпизоды -> out/ep01_12fps.mp4 (+ .wav)
python -m pixanime.cli render --episode 1
python -m pixanime.cli render --episode 2
python -m pixanime.cli render --episode 3

# GIF (собственный энкодер, без ffmpeg)
python -m pixanime.cli render --episode 1 --gif --fps 10

# отдельные кадры
python -m pixanime.cli still --episode 1 --times 3,16,40 --out-dir out/stills

# нейросеть: обучение (~20 минут на CPU) и сэмплирование
python -m pixanime.ml.train --steps 1500 --batch 4 --base 32 --out ckpt/pixvd.pt
python -m pixanime.ml.sample --cls 0 --n 3 --out out/ai_clip.gif
```

## 5. Структура

```
pixanime/
  palette.py canvas.py font.py sprites.py backgrounds.py
  anim.py effects.py scene.py timeline.py encode.py audio.py story.py cli.py
  ml/
    data.py     # клипы из движка = обучающий датасет
    model.py    # TinyVideoUNet + flow matching + сэмплер
    train.py    # цикл обучения, чекпоинты, кривая лосса
    sample.py   # генерация клипов в GIF/MP4/PNG
showcase/       # готовые mp4, gif, постеры
out/            # рабочая папка рендера (в git не входит)
```

## 6. Что можно улучшить дальше

* **3D-VAE** вместо пиксельной диффузии — тогда 256×256×32 станет реальным на GPU.
* **Текст-кондиционирование** (T5/CLIP-эмбеддинги + cross-attention) вместо класса сцены.
* **Интерполяция кадров** нейросетью: движок рисует 12 fps, модель дорисовывает до 24.
* **Больше вариативности спрайтов**: сейчас причёска/костюм параметрические — можно
  растить до генератора персонажей на диффузии (32×32 спрайты, как в `ml/`).
* **Сценарий как данные** (YAML/JSON), чтобы эпизоды писались без Python.
