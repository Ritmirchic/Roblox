# ASHES OF HUMANITY: LAST SIGNAL

A single-player 3D post-apocalyptic open-world survival action RPG that runs in the browser.
Everything — terrain, buildings, props, character models, textures, audio, quests and UI — is
generated by code in this repository. No third-party art, audio or story assets are used.

**Engine:** custom WebGL2 engine written for this project on top of **three.js r169** (MIT),
bundled with **esbuild 0.24**. It is not an Unreal/Godot project: those toolchains were not
available in the build environment, so the renderer, physics, streaming, AI, UI and audio
layers were written directly against three.js + Web Audio.

**Version:** 1.0.0 · **Status:** content-complete and playable end to end.

---

## Play

### Option A — the single file (recommended)
Open `dist/ashes_of_humanity.html` in a desktop browser (Chrome, Edge, Firefox, Safari 16+).
It is fully self-contained (≈950 KB, no network access needed) and can be launched straight
from disk. Double-clicking it is enough.

### Option B — the served build
```
npm install
npm run build
npm run serve        # http://localhost:8080
```
`index.html` loads `dist/game.js` as an ES module, so it must be served over HTTP.

**Requirements:** a WebGL2-capable desktop browser, keyboard and mouse. Headphones recommended.
**Optional URL flags:** `?lite=1` (low-end profile: no shadows, shorter draw distance, lower
internal resolution, fewer ambient NPCs/enemies), `?seed=12345` (world seed).

## Content

* **6 regions** — Dead Suburbs, Blackwood Forest, Industrial Zone, Forgotten City, Military
  Exclusion Zone, Red Wasteland — one seamless 1400 × 1000 m heightfield world with 33 discoverable
  sites, roads, a river valley, a toxic lake and an impact crater.
* **Story** — 8 acts, **40 main quests** and **45 side quests** with a full dialogue system,
  six named survivors (Nika, Anders, Yelena, Kravchuk, Mother Ash, the Signal) and a finale.
* **RPG progression** — level 1–50, XP curve, **4 skill trees / 26 nodes**
  (Combat, Survival, Engineering, Exploration).
* **Survival** — hunger, thirst, stamina, body temperature, radiation, infection, fatigue,
  stress, bleeding and fractures; six body parts with condition, splints and treatments.
* **Combat** — 13 weapons (melee, pistols, shotguns, rifles, SMG, crossbow) with mods,
  hitscan + projectile paths, limb/head damage multipliers, critical hits, recoil, durability,
  noise propagation, and **10 mutant types** with distinct behaviours plus **6 bosses**
  (Hollow King, Iron Abomination, Forest Matriarch, Contaminated Titan, Pale Commander,
  Last Signal).
* **World simulation** — day/night cycle (24 min), 7 weather states with fog/rain/lightning/
  radiation storms, 6 dynamic events, loot respawn, doors that open and block collision.
* **Items** — 43 item definitions, 10 × 7 grid inventory with weight, equipment slots, mods,
  crafting (23 recipes) and base building (10 structures with real colliders).
* **Audio** — entirely synthesised with Web Audio: weapons, impacts, footsteps per surface,
  creature vocalisations, weather, UI and an adaptive ambient score.
* **Presentation** — procedural PBR-ish materials (34 texture recipes with albedo/normal/ORM/
  emissive channels), a full custom HUD (compass, vitals, body status, weapon panel, hitmarkers,
  damage vignette, quest tracker) and nine interface screens with no external icon fonts.
* **Saves** — three localStorage slots plus autosave, serialising player, inventory, quests,
  skills, doors, loot, events, codex, world discovery and buildables.

## Tests

```
node tools/test.js            # 26 integration checks in jsdom, real systems, null renderer
npm run build && npm run serve
node tools/browser_test.js    # headless Chromium smoke test + screenshots in qa/browser/
```
The jsdom suite generates the real world and exercises movement, the shelter, inventory,
combat, loot, quests, skills, body damage, doors, NPC dialogue, shops, crafting, building,
world events, save/load, every UI screen, HUD and the finale boss.

The browser suite drives the **built** game in Chromium (SwiftShader) through four short
sessions and writes screenshots to `qa/browser/`: title screen, shelter/surface/camp/dialogue,
combat/weather/boss/save-load, and all interface screens. It requires the dev-only packages
`puppeteer-core` and `@sparticuz/chromium`.

## Measured on this machine

* World generation: ≈ 30 s in Node, ≈ 25–30 s in Chromium (progress bar shown).
* Static world: ≈ 1.34 M triangles, ≈ 340 draw calls with shadows off / ≈ 1 500 with shadows on.
* 33 POIs, 920 loot spots, 1 000 doors, 18 000+ collision boxes.

## Known limitations

* No motion-captured animation: characters use hand-authored procedural rigs (idle, walk, run,
  attack, death). Faces and hands are simplified at close range.
* Enemy navigation is steering + collision avoidance with region waypoints. It does not use a
  navigation mesh, so a mutant can get stuck on complex interior geometry.
* Interiors are lit by dynamic lights only (no baked lightmaps); without shadows some rooms
  look flatter than the exterior.
* Audio is synthesised — there is no voice acting, only text dialogue.
* The UI is designed for 1280 × 720 and wider; at smaller window sizes panels become cramped.
* QA was executed on software WebGL (SwiftShader) in headless Chromium. The rendering path is
  standard three.js/WebGL2 and was verified there, but frame rates on real GPUs were not measured
  in this environment.
* No installer: the Windows package is portable (one HTML file + batch launcher). There is no
  .exe because no Windows toolchain was available.
* Single-player only.
